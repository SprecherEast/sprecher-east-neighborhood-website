# AI agent tools (MCP)

> Generated by `npm run docs:generate` from the MCP plugin options in the agents module and the loaded Payload config. Do not edit by hand: change the code, then run `npm run docs:generate`.

AI agents connect to `Example` at the MCP endpoint (see [endpoints.md](endpoints.md)). Each request carries an API key that acts as an agent account; the key is checked by `checkKey` in `src/modules/agents/cms/mcp.ts`. For the tools the plugin makes, the content type’s access functions decide what a tool may do, and a key’s settings in Admin can only narrow that. The site’s own tools call Payload’s Local API themselves, which skips access unless a call says `overrideAccess: false`: each collection a tool reaches is marked “access checked”, “access bypassed” or “access depends on a value”, with the reason where the code gives one. “Reaches” is found by following the tool’s handler through the functions it calls in the source; a function passed in by the config is not followed, nor are the hooks a write sets off, which can write other collections (the search index, for example): each content type’s hooks are on its own page under Hooks. A collection passed to a shared helper is shown with what the helper does to it where its code shows that, otherwise as “operation not shown”. The calls counted are `find`, `findByID`, `findOne`, `count`, `findVersions`, `findVersionByID`, `findGlobal`, `findGlobalVersions`, `create`, `duplicate`, `update`, `updateOne`, `updateMany`, `updateGlobal`, `restoreVersion`, `delete`, `deleteOne`, `deleteMany`.

## Tools the site adds

Each field’s notes list every limit the JSON schema holds, the message of each custom check (`.refine`) written on the field, such as “each item once”, and a check that changes the value, such as `.trim()` (the note says whether it runs before the limits are counted or after). Not listed: the rules across fields, which the whole-input schema of each tool (`submitSuggestionInput` and `reportItemInput`, in `src/modules/agents/cms/tools/schemas.ts`) checks when the handler parses the input, and some of them are in no field description; `.strict()`, which refuses any field not listed here; and a check inside a union or a record, which is not read. A check on a field of an object (`evidence`, say) is written on that field of the tool with the name of the inner field in front.

### `submitSuggestion`

Suggest a draft.

Written in `src/modules/agents/cms/tools/submit.ts`.

Reaches: [`zeta`](content-types/zeta.md) (create (access checked), read (access bypassed)), [`alpha`](content-types/alpha.md) (operation not shown).
- `zeta`, read, from the comment on the function that makes the call: Hidden drafts. Only the id goes back.

| Input | Type | Required | Notes |
| --- | --- | --- | --- |
| `title` | string | yes | The title; 1 to 60 characters |
| `kind` | string | yes | one of b, a |
| `tags` | string[] | no | at most 3 items; custom check: Each tag once |
| `note` | string or null | no | at most 9 characters |
| `link` | string | no | matches `^https?:\/\/[^\s\|]+$` |
