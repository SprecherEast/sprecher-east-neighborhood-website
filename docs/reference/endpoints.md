# Endpoints

> Generated by `npm run docs:generate` from the loaded Payload config, the route files and the MCP setup. Do not edit by hand: change the code, then run `npm run docs:generate`.

Every way into the application that is not a site page, except what is listed under [Not shown](#not-shown): the route files, the files Next.js serves by name (robots, sitemap, icons, `public/`), the REST and GraphQL APIs Payload builds from the content types, the custom endpoints, and the endpoint AI agents use. Site pages are in [routes.md](routes.md). Who may do what on each content type is on its page, under Access.

## Files Next.js serves by name

Next.js makes a URL from a file in the `app` folder named for a metadata convention (robots, sitemap, icons, manifest, social images), and serves everything in `public/` from `/`. The conventions are those of the Next.js file-convention docs.

| URL            | File                     | Made by                                      |
| -------------- | ------------------------ | -------------------------------------------- |
| `/apple-icon`  | `src/app/apple-icon.png` | the file itself                              |
| `/favicon.ico` | `src/app/favicon.ico`    | the file itself                              |
| `/icon`        | `src/app/icon.svg`       | the file itself                              |
| `/robots.txt`  | `src/app/robots.ts`      | code                                         |
| `/sitemap.xml` | `src/app/sitemap.ts`     | code that reads site content through Payload |

In `public/`: `/brand/…`, `/images/…`.

### Routes Payload adds that an earlier endpoint takes first

Payload answers a request with the first endpoint of the type whose method and path match. These routes are in the type’s list, but an endpoint before them takes the requests they would get, so they are not reachable, or only for some requests. A path with an optional part (`:id?`) is asked with and without it, and `:name` matches one segment.

| Method | Path           | Content type          | Taken first by | Which requests              | Defined in                                       |
| ------ | -------------- | --------------------- | -------------- | --------------------------- | ------------------------------------------------ |
| DELETE | `/:id`         | `payload-preferences` | `/:key`        | every request               | payload                                          |
| GET    | `/:id`         | `payload-preferences` | `/:key`        | every request               | payload                                          |
| POST   | `/access/:id?` | `payload-preferences` | `/:key`        | only a request to `/access` | payload                                          |
| GET    | `/count`       | `payload-preferences` | `/:key`        | every request               | payload                                          |
| GET    | `/versions`    | `payload-preferences` | `/:key`        | every request               | payload                                          |
| POST   | `/verify/:id`  | `users`               | `/verify/:id`  | every request               | `src/modules/accounts/cms/verifyFromSiteOnly.ts` |

## Not shown

## MCP endpoint

AI agents connect at `/api/mcp`, with an API key that acts as an agent account. The key is checked by `checkAgentKey` in `src/modules/agents/cms/mcp.ts`. The tools, their input and the content types they reach are in [mcp-tools.md](mcp-tools.md). What runs on a timer is in [jobs.md](jobs.md).
